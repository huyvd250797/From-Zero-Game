# V2.1.0 — Visual Fidelity & Smooth Experience
Baseline: uploaded V2.0.1. Retain top-down orthographic camera; no Third-Person or First-Person.

## Graphics implementation
- `visual-fidelity.js`: analytic critically damped spring, bounded predictive camera position, LOD hysteresis, cooperative preparation helper, visual motion interpolation, frame statistics. Movement simulation remains 60 Hz. Camera yaw retains shortest-angle exponential interpolation; camera position/zoom/pitch use spring response. No gameplay time changes. Reset fixed-step/pacer on visibility changes.
- `renderer-three.js`: select visible chunks conservatively using existing projection. When high detail is not ready, display low detail, prioritize visible high detail then predicted low-detail neighbors; prepare at most one optional CPU geometry entry per render. LRU protects active/new entries. The synchronous creation of required visible low-detail geometry can still spike, and Three uploads buffers on first draw; the 2 ms cooperative target is not a hard GPU limit. No Web Worker or GPU timer query. Cache may exceed normal cap to retain all visible chunks plus one preparation slot.
- `three-bridge.js`: 128px shared procedural surface maps (renderer uses 128, helper default 64 for compatibility), mipmaps and anisotropy per quality; revised vertex contact shading on low walls, lighter ground. Not true screen-space AO. Existing PBR materials, FXAA and light footprint instancing retained. Shadow extent rounded to 4 world-unit steps, existing texel snapping, slightly adjusted normal bias. No new SMAA/MSAA, no advanced reflections or weather, no new character models. Texture memory increases compared to 64px maps.
- Adaptive resolution downshift reduced from 0.10 to ~0.075 (rounded to 0.01); existing 2-second sampling and 3-window recovery hysteresis preserved. FPS target unchanged. Actual visual quality and mobile performance require production GPU QA.

## Notifications
- `important-events.js`: explicit text policy for lifecycle milestones (birthday, jobs, promotion, marriage/birth, business, retirement, story, legal) and danger (critical health, lost housing, debts, vehicle energy). Unknown routine messages default to quiet. Routine mounting, parking, eating, work shifts, small purchases etc. do not create notification rows or toast. Action errors can still appear as transient feedback without entering the notification history.
- Existing `journal` is retained as a bounded 20-receipt internal compatibility buffer; original code uses it for operation results and regression tests. Visible journal uses `importantEntries`. Optional `importantJournal` stores up to 40 classified entries; initialized from available legacy entries on first new event/receipt, validated on load, no database migration. Earlier important entries already lost before upgrade cannot be reconstructed. Financial ledger, story/family/health/career histories remain unchanged. Rollback schema 1 accepts extra optional fields.
- Alerts are edge-triggered per exact warning text while the current condition persists, rearmed after recovery. Multiple newly active warnings may share the toast area; all appear in center. Session alerts clear at start; persistent important journal retained. New milestone detection compares text, so identical events within one simulated day may be coalesced.

## Diagnostics
Settings → Chẩn đoán chuyển động → Xuất báo cáo hiệu năng JSON. Includes renderer, viewport, preset, eco, measured frame interval stats, CPU preparation, cache and render metrics where supported. 1% low is reciprocal mean of slowest 1% of measured intervals; long frame means greater than twice nominal target interval (+0.5ms tolerance). No personal save data included. Metrics unavailable before a full sampling window; no GPU time claim.
