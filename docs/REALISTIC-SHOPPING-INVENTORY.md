# V3.4.0 — Realistic Shopping & Inventory

Baseline: V3.3.0. Retail is now a multi-product cart with three tabs (Sản phẩm, Giỏ hàng, Lịch sử), quantity controls, four categories, accent-insensitive search, per-item stock and a persistent total/action footer. Enter a retail location and choose Mua sắm vật phẩm, add items, review the cart, confirm, then complete the existing shop activity. A successful checkout clears the cart and shows the receipt. Draft carts are modal/session-only; closing the screen may discard the draft. No cash or goods change until the activity completes.

- Sixteen existing retail locations, sixteen canonical goods (excluding legacy phones and cooked-only recipes). Phones, vehicles and furniture remain in their dedicated purchase systems.
- Daily stock is independent per location and product. Small shops: food 40, ingredients/consumables 30, durable 6; larger catalogues (10+ goods): 80/60/12. Restocks at midnight by game day, lazily computed. No simulated NPC consumption or physical supplier delivery.
- Existing bag capacity 30 units, current economy price, cash-only, nearby, open for five more minutes, not mounted, not incarcerated, not ended. Reject duplicates/invalid IDs/quantities; require exact current quote (order ID, time, location and line prices). No partial checkout. Draft state handles both expense categories, stock and receipt before committing. One checkout takes five game minutes; food and supplies may appear as separate ledger entries to preserve financial reporting. All items go into existing inventory, not directly consumed.
- Receipt includes ID, timestamp, store, lines, quantity, unit price and total. Keep latest 60; daily stock remains independent of pruned receipts. Legacy saves initialize an empty shopping state with no invented receipts; schema remains 1.
- buyItem/buyReason share the checkout and stock with planning automation. If a selected store sells out, existing planner safety/condition behavior stops the activity; no autonomous retry across stores. Cooking, use and discard continue using canonical inventory.
- No dependency or SQL migration. Three.js r180 and Master Data 3.1.0 unchanged. Production must run npm ci and npm run build. Native QA is not production. Browser QA uses actual built modules loaded in Chromium with Canvas fallback and simulated localStorage; physical iOS/Android PWA and Three.js production not verified here.
