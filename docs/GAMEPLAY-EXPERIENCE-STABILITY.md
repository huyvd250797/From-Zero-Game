# V2.0.1 — Gameplay Experience & Stability
Baseline: user-provided V2.0.0. No Master Data, save schema, dependency or financial/survival-rule changes.

## Behavior
* Selecting a named destination while walking offers direct walking and each parked, reachable vehicle with fuel (bicycles exempt). The final destination remains separate from the current route leg. The pickup leg ends at the parked vehicle; normal ownership/proximity checks gate mounting; the second leg uses roadRoute. Arrival parks and opens the location. If pathfinding or mounting fails the journey is cleared with an error; manual walking suspends the final target, selecting the vehicle again or mounting resumes it. Esc / cancel clears the journey. No route persistence across reloads; state and vehicle position persist via the existing save.
* Every viewport-intersecting street-lamp illumination footprint is included, with padding. Three.js uses two instanced batches (bulb + soft additive world-space ground texture, depth tested) and a quality-bounded supplemental PointLight pool. The ground/bulb base does not disappear when a PointLight is reassigned. Slots fade out before relocating and fade in; same street-lamp coordinates at both LODs. No individual shadow maps; light footprints approximate static illumination rather than full lightmap or real-time multi-light indirect GI. Legacy renderers use approximate colored ground patches and bulb geometry.
* NPC labels appear within 6 world metres, remain until >8; max three nearest eligible labels, line-of-sight and viewport checks. Names are not selected solely by zoom. Underlying NPC behavior and interactions unchanged.
* HUD defaults: minimap off (drawCityMap not called for mini), floating joystick on (idle faint guide, pointer anchor at first touch, clears on release/cancel/blur). Four visible quick buttons; character profile and calendar reachable through menu. Camera collapsed by default on both PC and mobile; context area only when relevant. Full map available independently. HUD preferences use fromzero.hud.v201, separate from save. Existing page zoom guard unchanged.
* Individual SVGs cover all 19 canonical goods, used for inventory, shop and recipes. Original procedural shapes, no external assets.
* MotionClock uses fixed 1/60 s movement ticks, catch-up bounded to 0.2 s as before; render position interpolated and shared with camera and player label; active vehicle display position follows same interpolated coordinate. Simulation clock remains separate. FramePacer carries forward the fractional target deadline, resets on mode switch/long stalls; 90 and 144 Hz will still have quantization to display refresh. Close camera holds lifted pitch for .35 s and limits descent to 22°/s. Directional shadow center quantized in light-space to the shadow texel. No change to collision/fuel/financial rules. Camera still uses exponential smoothing; asynchronous GPU streaming and a full spring/physics camera are not part of this fix.

## QA
511 independent tests passed, native preview build 75 fingerprinted assets. Ideal 10 s scheduler samples: 60 Hz 600→600; 90 Hz 450→600; 120 Hz 600→600; 144 Hz 480→600 at target 60 FPS. This tests cadence math, not real FPS or GPU load. 30-day survival unchanged: 5,180,000 / 3,050,000 / 705,000 VND, health 100 at all three difficulties.

`npm ci` then `npm run build`, output dist, Node 22.x; same Vercel settings. Three.js r180 required, production gate preserved. Offline install in this environment fails ENOTCACHED, so production build and real Three.js integration are not certified. Chromium QA uses Canvas fallback. After deploy, validate: walk→vehicle→destination; manual interrupt and resume using vehicle; pan/zoom at night with all visible lamps lit; move on iPhone and compare p95 while walking/driving; NPC labels at 6/8 m; no browser page zoom on iOS; backup and offline reload.
