# V2.9.0 — Life Planning & Automation
Baseline: user-provided V2.8.0. Preserve city, camera, character models, interior and canonical gameplay.

## User workflow
Menu cuộc đời → Kế hoạch & tự động hóa (or Lịch sinh hoạt hằng ngày → Mở kế hoạch & tự động hóa). Add a task or append a template (max 24 tasks). Configure start/departure hour, 15–360 minute grace window, repeat daily / selected weekdays / calendar month day / one game day, travel mode (auto, walk, owned vehicle, bus, taxi) and condition (always, as needed, contract workday). Monthly dates missing in a month are skipped. Day previews and next 7/30 days list scheduled tasks, not promises of feasibility. Start button opts in at speed 1×. HUD shows task/route stage, tap to stop and see history. Trusted pointer or key input stops automation (including camera interactions), as does opening a modal, pause, title screen, custody or ending. Do not use automation while using manual controls; explicitly restart after stopping. Reload/import never auto-runs a saved active task.

## Action policy
`planner-state.js` owns validation, defaults, ID allocation, recurrence records, budget and reload suspension. `life-planner.js` resolves work, temporary work, class, library study (programming), meal, water, sleep, hygiene, relax, purchase food, purchase water, clinic treatment and return home. `main.js` coordinates foreground game time and normal movement using existing walk/owned vehicle/public journey functions; at a destination it suppresses the usual menu and calls the canonical action after verifying proximity. No teleport. Owned vehicles must be available and sufficiently fueled. Auto mode estimates fastest eligible route with current action cost reserved from fare budget; time estimates not guarantees. Work task departs at scheduled time, waits until 08:00 and cannot accept later than 09:00. Rest/health/food use appropriate existing places, free water and shelter fallback if homeless. No automatic job applications, course enrollment, property purchase, loan, investment or business setup.

## Safety, costs, persistence
Direct expenses (goods, clinic, paid transit) max 150,000đ per game day by default and 60,000đ cash reserve; adjustable. Systemic recurring bills, loan obligations, already purchased fuel and manual spending are outside this budget. Fare charged once upfront, no refund on interruption. Preflight checks current and final critical needs/health/stress on a structured clone; only commit successful canonical action and check cash reserve. Not minute-by-minute safety cancellation within atomic long action. Existing work/study duration, needs, reward and limits retained. Budget checked again at destination. Arrival deadlines are latest action start, not completion. Stop on unsafe state, failed route/action or save failure; no repeated warning spam. Missed/condition-skipped tasks logged separately, not in regular notification center. History capped 120 with unique task/day; edit/delete does not reset current-day completion; prior days not replayed. Save schema 1 optional planner object, validated, legacy defaults disabled. Session route not resumed on reload; running task becomes interrupted; existing fare remains spent. Simulation only while active foreground gameplay, no real-world scheduling or background execution. Atomic activity advances time using existing game logic and does not animate each step inside 3D interiors. Health preflight is conservative and may stop a long action that requires manual recovery. Budget does not guarantee solvency against automatic obligations.
