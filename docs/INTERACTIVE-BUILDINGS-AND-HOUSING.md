# V2.8.0 — Interactive Buildings & Housing
Baseline: V2.7.1 Smart Mobility & Rig Cache Stability Fix.

## Actual implementation
- `interior-world.js`: 41 public places mapped to physical service stations and existing canonical actions. 11 homes use 1/2/4 connected areas according to capacity. Entry/exit and time checks reuse the exterior position and access rules. Private homes require active tenancy; no automatic entry to unowned homes. No changes to exterior map, population, vehicles or canonical economics.
- `housing-design.js`: local room coordinates, room boundaries and collision cells, unique reachable interaction stations, per-property draft and durable design save. Furniture can move within a room or to another room without straddling partitions. Four floors and four walls. Existing purchased upgrades retained; built-in furnishings are presentation fixtures, not new market items or extra comfort. Invalid overlaps, out-of-bounds, blocked entry/required room centers, and unreachable stations rejected. On import, conflicting saved positions caused by future fixtures fall back safely, preserving other valid preferences. Optional `housing.decorations` validated structurally; commit validates the complete layout. Schema 1 unchanged. Old saves have no decoration field. New decoration settings do not change cash or comfort. Renters can customize at no cost (game design choice).
- `interiors.js`: shared city `Mesh` builder, planar tile floor, roofless cutaway, physical partition walls and door gaps, furnishing geometry and 90-degree vertex rotation. Indoor scale is deliberately compact game-space units, not real property area. `interior-three.js` uses actual Three.js WebGL renderer with orthographic camera, MeshStandardMaterial, shared avatar rigs and animation; independent bounded interior scene, geometry replacement without restarting WebGL on edit; dynamic route and player ring; GPU resources disposed on exit. Canvas fallback projects the same triangles, but depth sorting and visual quality are limited and there is no GPU lighting. Interior currently uses simpler fixed lighting, not the full outdoor weather/postprocessing/shadow pipeline. No new GLB furniture assets.
- `main.js`: full viewport scene instead of small preview; follow camera, overview, zoom, yaw, two-pointer pinch, keyboard WASD/arrow, Shift, E, mobile joystick/run button, click floor/objects, local route guide, contextual station actions. Walking uses 2.5 units/s, running/auto-route up to 4.8; local collision radius .20. Exterior position is maintained at the door; no simulation of collision against NPC occupants, who are visual participants. Time advances with existing tickClock in room (pauses if game paused, edit mode, menus, or hidden); access expiry returns outside. Action uses original business logic and ActivityRun exactly-once completion/cancel; return to station. Menus for purchases, employment etc. remain accessible, not a fully seamless world interior or multistory building. Close/escape is emergency exit. Indoor position is session-only; reload returns outside. No new cooking, laundry or TV gameplay for decorative fixtures. Family avatars baked into the room mesh, public residents retain existing animation.
- Desktop and mobile retain city views and PWA restrictions. No changes to master-data files or core gameplay balance. Previous V2.7.1 rig-cache fix retained.

## QA / deployment
`npm ci`, `npm test`, `npm run build` (mandatory real Three runtime tests), `npm run verify:release`, `npm run smoke:http`. `npm run build:native-preview` only for QA; do not deploy that output. Native QA can be tested without the unavailable npm dependency. Browser QA uses Chromium Canvas fallback, blob module imports and mock localStorage; verifies full screen, wall/floor/rotation save, keyboard, mobile joystick, desktop path to bed and cancellation/return. No actual iPhone GPU, WebGL renderer or PWA origin validation here. Three.js r180 dependency not cached; production test requires registry access. Vercel preset Other, Node 22, install `npm ci`, build `npm run build`, dist. Export save before replacing source. No SQL migration.
