# From Zero V3.2.0 — Immersive Audio Engine

Baseline: supplied V3.1.1 Mobile HUD Refinement. No save schema, master data, logo or gameplay rule changes. All audio is original procedural synthesis using Web Audio; no external recordings, downloads or network requests.

## Recovery
- Lazy AudioContext creation and resume on trusted pointer, keyboard, touch or click events. Resume attempts time out after 1.8 seconds; new trusted gestures can supersede pending attempts. A generation token avoids stale results overriding new requests. A closed context is recreated; a failed graph can be explicitly rebuilt without resetting mixer preferences.
- Visibility, pagehide/pageshow, focus, freeze/resume support; hide mutes and suspends the graph; foreground retries resume, with trusted gesture fallback. Some iOS audio interruptions require a new tap. No attempt to bypass browser autoplay policy or OS output routing.
- Settings → Âm thanh & nhạc nền: Bật / nghe thử (700 ms tone), Khôi phục âm thanh (rebuild), Mặc định. Diagnostic reports browser/PWA mode, context state, transient voices and approximate output RMS. A running context or RMS signal does not prove the physical speaker is audible. Volume settings are preserved in fromzero.audio.v1. A zero master or muted preview groups will not be overridden.

## Soundscape
- Day/night and district-dependent city bed, birds, crickets, wind and rain. Rain is attenuated indoors, thunder is synthesized at bounded intervals during storms. Wet footsteps differ from dry and indoor steps. Activity cues are inherited. Commercial interiors get occasional synthesized rustle/typing; not recorded speech.
- Seven motor profiles (motorbike, combustion car, luxury car, EV, truck, bus, taxi) vary oscillator shape, frequency, low-pass filter and level. Bicycle uses a mechanical cue, not a motor. Public transit uses the current leg: no motor during walking or waiting. Passing vehicles from lane traffic, scheduled buses and available named NPC presentation are spatially mixed; boarded bus is filtered. Horn cue is an ambient approximation when nearby vehicles include stopped traffic, not an actual traffic violation/AI event.
- Up to 3 nearby traffic actors per sample, 1 nearby talker, 20 short voices, 4 noise beds, 2 engine oscillators. Short voices disconnect on end, background hides/suspends, 100 ms audio update cadence, bus candidates cached per half game minute. Stereo panning optional. Original chord motif adds a sustained layer, no third-party music. Seven mixer groups retained: master, ambient, weather, vehicles, activities, music, UI.

## QA and device acceptance
- 698 prior unit tests + 11 new tests; Native QA assets and HTTP integrity; 30-day balance regression. Real Chromium AudioContext verified via locally loaded built module (desktop/mobile emulation) with nonzero output RMS, master mute, suspend/resume, rebuild and standalone detection. These tests do not install a PWA or verify physical audio routing. Browser policy blocked loopback navigation. Production Three.js dependency unavailable offline; production gate retained.
- On deployed HTTPS version: in Safari and installed Home Screen PWA, open Settings → Âm thanh & nhạc nền, tap Bật / nghe thử; verify audible tone, context running and media volume. Test walking, cycling, motor vehicles, bus walk/wait/ride, rain and indoor scenes; toggle master and individual groups. Return to home screen, lock/unlock, switch apps, and interrupt with another audio app; return and confirm recovery or tap once. Try Khôi phục âm thanh if necessary. Verify offline after successful PWA install/cache, including app reopen and no network. Test headphones/Bluetooth separately. Check media volume and silent mode; no browser code can guarantee system output. Do not claim iPhone/PWA hardware acceptance until tested.
